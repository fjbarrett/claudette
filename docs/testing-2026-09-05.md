## Defects found and fixed

- Verification incorrectly accepted package-manager help commands, Make dry
  runs, and pytest collection selected through `PYTEST_ADDOPTS` or `addopts`
  overrides. Regression cases failed before the correction and pass afterward.
- Redirecting output to `/dev/null` incorrectly marked a review as having edited
  source, causing unnecessary verification requests. Discarded output is now
  excluded while actual output-file writes still invalidate verification.
- A nested macOS `sh -lc` emitted `/etc/profile: Operation not permitted` under
  strict Bash isolation. The `/etc` alias now permits metadata reads; its
  `/private/etc` target was already readable. File-write, outside-file, signal,
  Apple Event, and network restrictions remain covered by the sandbox tests.
- The review evaluation had brittle positive wording checks and missed
  speculative coverage claims. Its assertions now accept equivalent Markdown
  wording and reject the observed unexecuted “100% coverage” predictions.

fixtures; no paid-provider fallback or user-project edits were used.

Kimi's Python CLI implementation passed its checks but added prose to a required
exact final token. Its other failed scenario was a review that guessed runtime
coverage and misstated source line numbers. Both models consistently recognized
that collection-only coverage is not executed-test coverage, but some reviews
still predicted 100% coverage without running tests. Those predictions remain
failures, including when qualified as guesses.

The five-repeat reports originally scored 5/5 with the weaker oracle. Manual
inspection found three speculative answers; the stronger negative assertions
rescore the same retained responses as 3/5 and 4/5. Original reports were kept,
not overwritten. These results do not establish that model reviews are always
accurate or that arbitrary shell commands can be classified perfectly.
