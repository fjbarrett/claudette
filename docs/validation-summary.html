Confirmed Findings

  1. The CLI tool-loop suite is fixed. Tool-call output now includes stable raw tool-name markers, which keeps the richer formatted UI while preserving deterministic stdout contracts for automated assertions.
  2. The stress-suite startup path is now resilient. The test no longer depends on fixed port 14323; it reserves a free port at runtime and surfaces startup failures from stderr or early process exit immediately.
  3. Core server behavior remains intact. Independent smoke checks against the live server on 127.0.0.1:4321 still succeed, and the full test rerun confirms the earlier runtime assessment.
  4. The repo is validation-clean but test runs generate local session artifacts. The application persists sessions and transcripts during some integration tests, so the working tree picks up untracked runtime files unless those paths are ignored or cleaned.

Recommended Next Steps

  1. Add data/sessions and data/transcripts to .gitignore if you do not want validation runs to leave untracked runtime artifacts.
  2. Consider splitting the live Ollama stress loop into a separate slow test target for faster default local iteration.
  3. Keep the raw tool-name alias in the CLI output so UI polish does not silently break test contracts again.
  4. Use the benchmark harness for repeated model comparisons now that the baseline app validation is clean.
